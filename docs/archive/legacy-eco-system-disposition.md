## Preserve as source/document history

- Authored outer source modules and documentation.
- Readmes, changelogs, architecture, handoff, and experiment records.
- Playbooks and historical reports.
- Tests, including failing tests, as regression evidence.
- Both duplicate trees until an exact checksum/diff identifies identical, unique, and drifted files.
- A manifest for excluded data recording relative path, byte size, modification time, SHA-256, category, and disposition.

## Keep out of the versioned source archive

These remain local until separately reviewed; exclusion from Git is not deletion.

- Logs and `*.log`.
- Python bytecode and test caches.
- Generated embeddings and `*.npy` stores.
- Database backups and copied database variants.
- Vendored `three.min.js` copies.
- Deterministically reproducible outputs.
- Nested files proven byte-identical to a chosen canonical source file.

## Canonicalization procedure

1. Use the outer tree as a provisional comparison base, not as automatic authority.
2. Generate sorted manifests for outer and nested trees containing SHA-256, byte size, relative path, category, and disposition.
3. Normalize only path prefixes; never normalize contents before hashing.
4. Classify items as `identical_duplicate`, `nested_only`, `outer_only`, or `same_path_drift`.
5. Retain both copies of unique or drifted files until donor-specific tests identify a canonical implementation.
6. Record the command, timestamp, tool version, and final manifest hash.
7. Copy only qualified source/docs into a curated archive after review; do not delete the original tree.

Example read-only checksum pipeline:

```sh
find <exact-tree> -type f -print0 |
  sort -z |
  xargs -0 sha256sum
```

The implemented manifest generator should additionally capture byte sizes and portable relative paths.
