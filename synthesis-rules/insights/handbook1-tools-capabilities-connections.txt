-----------------------------------------------------------------------------
1.1 READ TOOL
-----------------------------------------------------------------------------

OVERVIEW
--------
The Read tool loads file contents from the filesystem. It's the primary way
to consume existing files, documents, and code for analysis or processing.

OFFICIAL CAPABILITIES
---------------------
- Read any file from filesystem (requires absolute path)
- Handle text files, images, PDFs, Jupyter notebooks
- Pagination support for large files (offset/limit)
- Line numbers in output (cat -n format)
- Automatic format detection and processing

DISCOVERED PROPERTIES
---------------------
✓ Absolute paths required (relative paths fail)
✓ Images/PDFs processed natively (multimodal)
✓ Jupyter notebooks return all cells with outputs
✓ Lines >2000 chars get truncated
✓ Must read before Edit/Write on existing files (enforced)
✓ Returns empty warning if file exists but is empty

PERFORMANCE CHARACTERISTICS
---------------------------
Speed: Fast (<2s for normal files)
Scale: Handles files up to context limits
Optimal: Files <2000 lines without pagination
Latency: +500ms for images/PDFs

ENABLES CLAUDE API CAPABILITIES
-------------------------------
✓ RAG - Read documents to provide retrieval context
✓ Summarization - Read source material for summarization
✓ Classification - Read training examples
✓ PDF Summarization - Direct PDF upload capability
✓ Contextual Embeddings - Read documents for contextualization
✓ Text-to-SQL - Read schema information

TYPICAL USAGE PATTERNS
----------------------
1. Single File Read
   Read(file_path="/absolute/path/to/file.txt")

2. Paginated Large File Read
   Read(file_path="/path/to/large.log", offset=1000, limit=500)

3. Parallel Multiple File Read (CRITICAL OPTIMIZATION)
   [Read multiple files in single message]
   - 5 files in parallel vs sequential = 5x speedup
   - Essential for efficient workflows

4. Image/PDF Read
   Read(file_path="/path/to/document.pdf")
   - Returns visual + text content
   - Enables document analysis

EMERGENT WORKFLOW PATTERNS
--------------------------
Pattern: Search → Read → Extract
  Glob/Grep → locate files → Read → extract data → Write JSON
  Example: Find notebooks → Read guides → Extract capabilities

Pattern: Speculative Parallel Reads
  Read multiple potentially useful files in parallel
  Better to read and not need than to read sequentially
  Example: Read all related config files at once

Pattern: Validation Reading
  After Write/Edit → Read to confirm changes
  Critical for quality assurance

Pattern: Structured Extraction
  Read → parse structure → extract specific data → format output
  Example: Read JSON → extract nodes → validate → process

ANTI-PATTERNS
-------------
✗ Reading same file repeatedly (use context memory)
✗ Reading without specific purpose (wastes tokens)
✗ Reading entire large files without Grep first
✗ Using relative paths (will fail)
✗ Not using parallel reads when possible (slower)

CONNECTS TO
-----------
Tools: Often paired with Grep (locate content) or Glob (find files)
Capabilities: Foundation for RAG, Summarization, Classification
Techniques: Enables Contextual Embeddings, Citations
Workflows: First step in most analysis workflows

REAL-WORLD USAGE (FROM KGF PROJECT)
-----------------------------------
- Read 30+ files across capabilities, agents, skills, techniques
- Read schema documents for understanding structure
- Read database.py to understand API structure
- Read READMEs for overview information
- Used parallel reads extensively (5-10 files per message)
Total: ~15 Read tool invocations, 30+ files processed

1.2 WRITE TOOL
-----------------------------------------------------------------------------

OVERVIEW
--------
The Write tool creates new files or overwrites existing files. It's the
primary output mechanism for generating code, documentation, data files,
and any persistent results.

OFFICIAL CAPABILITIES
---------------------
- Create new files with any content
- Overwrite existing files
- Must Read before Write on existing files (enforced)
- Returns confirmation with file path
- Handles any string content (JSON, code, text, etc.)

DISCOVERED PROPERTIES
---------------------
✓ Overwrites existing files (destructive - be careful)
✓ Read enforcement prevents accidental overwrites
✓ Creates parent directories? (needs validation)
✓ Immediate write (no streaming)
✓ Content parameter accepts unlimited length (context permitting)
✓ No built-in formatting (pass formatted strings)

PERFORMANCE CHARACTERISTICS
---------------------------
Speed: Fast (<1s regardless of size)
Scale: Limited by context window for content parameter
Optimal: Any size file that fits in context
Latency: Minimal, near-instant response

ENABLES CLAUDE API CAPABILITIES
-------------------------------
✓ Skills - Create documents (conceptual xlsx/pptx/pdf creation)
✓ Code Generation - Write complete source files
✓ Batch Processing - Write results to output files
✓ Building Evals - Create test scripts and eval files
✓ JSON Mode - Write structured JSON output
✓ Metaprompt - Write generated prompt templates

TYPICAL USAGE PATTERNS
----------------------
1. Create Structured Data
   Write JSON files from extracted/processed data
   Example: Write(file_path="/path/data.json", content=json_string)

2. Generate Documentation
   Write comprehensive docs from analysis
   Example: Write(file_path="/path/README.md", content=markdown)

3. Create Executable Scripts
   Write Python/Bash scripts for automation
   Example: Write(file_path="/path/script.py", content=python_code)

4. Progressive Assembly
   Write partial results → continue analysis → Write more
   Better than single massive file
   Example: Write nodes → Write edges → Combine later

EMERGENT WORKFLOW PATTERNS
--------------------------
Pattern: Extract → Structure → Write
  Analyze content → Structure as JSON/code → Write file
  Essential for data processing workflows

Pattern: Multiple Writes in Sequence
  Write separate files → combine with tools later
  Example: Write 5 node files → combine with jq → final graph

Pattern: Write → Validate → Fix Loop
  Write → Test with Bash → Fix issues → Write again
  Quality assurance through iteration

Pattern: Template + Data → Write
  Generate content from template + data → Write output
  Enables repeatable generation patterns

ANTI-PATTERNS
-------------
✗ Writing without validation (test generated code first)
✗ Writing huge files in one call (split if needed)
✗ Overwriting without Read on existing files (loses data)
✗ Not confirming write success (check response)
✗ Writing without clear purpose (creates clutter)

CONNECTS TO
-----------
Tools: Follows Read (for validation), paired with Bash (for testing)
Capabilities: Output mechanism for all generation capabilities
Techniques: Implements JSON Mode, enables Batch Processing results
Workflows: Final step in extraction/generation workflows

REAL-WORLD USAGE (FROM KGF PROJECT)
-----------------------------------
- Wrote 5 separate node definition files (JSON)
- Wrote relationships file (JSON)
- Wrote migration script (Python, 350 lines)
- Wrote documentation files (Markdown, comprehensive)
- Wrote analysis documents for reference
Total: ~15 Write operations creating ~100KB of content

1.3 EDIT TOOL
-----------------------------------------------------------------------------

OVERVIEW
--------
The Edit tool performs exact string replacement in existing files. It's the
surgical tool for targeted modifications without rewriting entire files.

OFFICIAL CAPABILITIES
---------------------
- Exact string replacement in files
- Replace all occurrences with replace_all flag
- Must Read file first (enforced by system)
- Preserves file structure and formatting
- Fails if old_string not unique (safety feature)

DISCOVERED PROPERTIES
---------------------
✓ Requires exact match (whitespace-sensitive)
✓ Preserves indentation after line number prefix
✓ Read enforcement prevents blind edits
✓ Graceful failures with clear error messages
✓ Can chain multiple edits in sequence
✓ replace_all for variable renaming

PERFORMANCE CHARACTERISTICS
---------------------------
Speed: Fast (<1s for small changes)
Scale: Efficient even for large files (only changes delta)
Optimal: Small, targeted changes
Latency: Minimal, near-instant

ENABLES CLAUDE API CAPABILITIES
-------------------------------
✓ Evaluator-Optimizer Pattern - Edit → validate → edit loop
✓ Iterative Refinement - Repeated improvements
✓ Code Refactoring - Systematic changes
✓ Configuration Updates - Modify settings
✓ Bug Fixing - Targeted corrections

TYPICAL USAGE PATTERNS
----------------------
1. Configuration Update
   Edit .env files to change settings
   Example: Edit(file_path=".env",
               old_string="DATABASE=old.db",
               new_string="DATABASE=new.db")

2. Targeted Function Fix
   Edit specific function without touching rest of file
   Example: Fix bug in single function definition

3. Iterative Refinement Loop
   Edit → Test → Edit → Test until correct
   Example: Refine algorithm through iterations

4. Batch Variable Rename
   Use replace_all to rename throughout file
   Example: Rename variable across all occurrences

EMERGENT WORKFLOW PATTERNS
--------------------------
Pattern: Read → Edit → Validate
  Read file → Make changes → Test with Bash → Confirm
  Essential for quality assurance

Pattern: Multiple Sequential Edits
  Edit section 1 → Edit section 2 → Edit section 3
  Systematic refactoring approach

Pattern: Edit → Read → Confirm
  Edit → Read back changes → Verify correctness
  Validation through re-reading

Pattern: Evaluator-Optimizer Loop
  Edit → Test → Evaluate → Edit based on feedback → Repeat
  Implements evaluator-optimizer agent pattern

ANTI-PATTERNS
-------------
✗ Editing without reading first (impossible, enforced)
✗ Non-unique old_string (causes edit to fail)
✗ Including line numbers in old_string (breaks matching)
✗ Making changes without testing (risky)
✗ Editing when Write would be clearer (use right tool)

CONNECTS TO
-----------
Tools: Always preceded by Read, often followed by Bash (test)
Capabilities: Core of Evaluator-Optimizer pattern
Techniques: Enables Iterative Refinement workflows
Workflows: Central to refactoring and improvement loops

REAL-WORLD USAGE (FROM KGF PROJECT)
-----------------------------------
- Edited backend/.env to point to new database
- Changed DATABASE_PATH from gemini to claude db
- Would use extensively in code refactoring projects
Total: Minimal use in data extraction project (more for code work)

1.4 GLOB TOOL
-----------------------------------------------------------------------------

OVERVIEW
--------
The Glob tool performs pattern-based file searches. It's the fastest way to
discover and enumerate files matching specific patterns.

OFFICIAL CAPABILITIES
---------------------
- Fast pattern-based file search
- Works with any codebase size
- Standard glob patterns (**, *, ?, etc.)
- Returns paths sorted by modification time
- Optional path parameter to narrow search

DISCOVERED PROPERTIES
---------------------
✓ Extremely fast (<100ms typically)
✓ Returns empty list if no matches (not error)
✓ Can search within specific subdirectories
✓ Scales well even with large codebases
✓ Modification time sorting is default
✓ Returns absolute paths

PERFORMANCE CHARACTERISTICS
---------------------------
Speed: Extremely fast (<100ms)
Scale: Handles codebases of any size
Optimal: Any pattern complexity
Latency: Near-instant response
Winner: Fastest tool available

ENABLES CLAUDE API CAPABILITIES
-------------------------------
✓ RAG - Find relevant documents for retrieval
✓ Code Analysis - Locate files for review
✓ Batch Processing - Find all input files
✓ Classification - Find example files
✓ Summarization - Locate documents to summarize

TYPICAL USAGE PATTERNS
----------------------
1. Find Files by Extension
   Glob(pattern="**/*.ipynb")
   Returns: All Jupyter notebooks recursively

2. Find in Specific Directory
   Glob(pattern="**/*.py", path="/project/src")
   Returns: All Python files in src/

3. Multiple Patterns in Parallel
   [Glob for .py, Glob for .md, Glob for .json]
   Parallel discovery of different file types

4. Discovery Phase
   Start project by finding all relevant files
   Example: Glob notebooks → Glob configs → Glob docs

EMERGENT WORKFLOW PATTERNS
--------------------------
Pattern: Glob → Read Pipeline
  Glob finds files → Read each file → Process content
  Foundation of file processing workflows

Pattern: Structure Discovery
  Use Glob patterns to understand codebase organization
  Example: Glob("**/test_*.py") reveals test structure

Pattern: Parallel Discovery
  Multiple Glob calls in one message for different file types
  Faster than sequential discovery

Pattern: Verification Before Operations
  Glob to check if files exist before complex operations
  Example: Glob → confirm files present → proceed

ANTI-PATTERNS
-------------
✗ Using when exact path known (just use Read)
✗ Too broad patterns returning thousands of files
✗ Using Glob when Grep is needed (wrong tool)
✗ Sequential Glob when parallel possible (slower)

CONNECTS TO
-----------
Tools: Always followed by Read (or Grep for further filtering)
Capabilities: Enables RAG document discovery, Batch Processing
Techniques: Foundation for systematic file processing
Workflows: First step in discovery and enumeration workflows

REAL-WORLD USAGE (FROM KGF PROJECT)
-----------------------------------
- Found all .ipynb files in misc/ folder (13 files)
- Located .md files in capabilities/ (5 READMEs)
- Found Python scripts in backend/ (3 files)
- Discovered migration scripts (none found, informed approach)
Total: ~5 Glob operations finding ~50 files across project

-----------------------------------------------------------------------------
1.5 GREP TOOL
-----------------------------------------------------------------------------

OVERVIEW
--------
The Grep tool performs content search using regex patterns. It's built on
ripgrep (not grep) for high-performance text search across files.

OFFICIAL CAPABILITIES
---------------------
- Full regex syntax support
- Three output modes: content, files_with_matches, count
- Filter by file type or glob pattern
- Context lines available (-A, -B, -C)
- Multiline mode for cross-line patterns
- Case-insensitive search option

DISCOVERED PROPERTIES
---------------------
✓ Uses ripgrep (faster than grep)
✓ Respects .gitignore by default
✓ Output limited to prevent overwhelming responses
✓ Can show line numbers with -n flag
✓ head_limit controls output truncation
✓ Pattern syntax is ripgrep (literal braces need escaping)

PERFORMANCE CHARACTERISTICS
---------------------------
Speed: Very fast (typically <1s)
Scale: Handles large codebases efficiently
Optimal: Specific patterns in large file sets
Latency: Minimal even on large searches

ENABLES CLAUDE API CAPABILITIES
-------------------------------
✓ RAG - Semantic search within documents
✓ Code Analysis - Find patterns and definitions
✓ Classification - Locate examples matching criteria
✓ Citations - Find specific text for sourcing
✓ Text-to-SQL - Find schema definitions

TYPICAL USAGE PATTERNS
----------------------
1. Find Files Containing Pattern
   Grep(pattern="def.*function_name", output_mode="files_with_matches")
   Returns: Files containing function definitions

2. Show Matching Lines
   Grep(pattern="TODO", output_mode="content", -n=True)
   Returns: Lines with TODO comments and line numbers

3. Count Occurrences
   Grep(pattern="import.*pandas", output_mode="count")
   Returns: How many times pandas is imported

4. Search with Context
   Grep(pattern="error", output_mode="content", -C=3)
   Returns: Error lines with 3 lines before/after

EMERGENT WORKFLOW PATTERNS
--------------------------
Pattern: Grep → Read
  Grep finds files → Read specific files for details
  Faster than reading all files first

Pattern: Pattern Discovery
  Grep for patterns to understand codebase conventions
  Example: Grep("class.*:") finds all class definitions

Pattern: Validation Grep
  Grep to verify expected content exists
  Example: Grep for function to confirm implementation

Pattern: Multi-Stage Filtering
  Grep broad pattern → Grep narrower pattern in results
  Progressive refinement of search

ANTI-PATTERNS
-------------
✗ Grepping when Glob sufficient (wrong tool)
✗ Not using type/glob parameters (searches too much)
✗ Overly complex regex when simple string works
✗ Using Bash grep instead of Grep tool (slower, less integrated)

CONNECTS TO
-----------
Tools: Works with Glob (narrow files first), feeds into Read
Capabilities: Enables RAG retrieval, Citation sourcing
Techniques: Foundation for systematic code analysis
Workflows: Search and locate step in processing pipelines

REAL-WORLD USAGE (FROM KGF PROJECT)
-----------------------------------
- Searched for "migrate" in backend/ (found none)
- Searched for "import" scripts (found none, informed migration approach)
- Would use extensively in code analysis projects
- Validated absence of existing migration infrastructure
Total: Minimal use in this project (mainly Glob-based discovery)

2.1 BASH TOOL
-----------------------------------------------------------------------------

OVERVIEW
--------
The Bash tool executes shell commands in a persistent session. It's the
bridge to the system, enabling command execution, testing, git operations,
and data processing.

OFFICIAL CAPABILITIES
---------------------
- Execute shell commands in persistent session
- Default 2-minute timeout (configurable to 10 min)
- Background execution with run_in_background flag
- State maintained across calls (cd, env vars persist)
- Git operations with safety protocols
- Output truncated at 30,000 chars

DISCOVERED PROPERTIES
---------------------
✓ Persistent shell session (state maintained)
✓ Proper quoting essential for paths with spaces
✓ Can chain commands with && (sequential) or ; (independent)
✓ Background mode for long operations
✓ Git has special safety protocols (no --force by default)
✓ Can monitor background with BashOutput tool

PERFORMANCE CHARACTERISTICS
---------------------------
Speed: Varies by command (instant to minutes)
Scale: Can handle large data processing
Optimal: Short commands or background long ones
Timeout: Default 2 min, max 10 min

ENABLES CLAUDE API CAPABILITIES
-------------------------------
✓ Batch Processing - Run scripts on multiple inputs
✓ Agent Patterns - Execute worker tasks
✓ Building Evals - Run test suites
✓ Text-to-SQL - Execute sqlite3 commands
✓ Skills - Run data processing pipelines

TYPICAL USAGE PATTERNS
----------------------
1. Command Chaining
   Bash(command="mkdir output && cp file.txt output/")
   Sequential operations with failure propagation

2. Parallel Execution
   [Bash(cmd1), Bash(cmd2), Bash(cmd3)] in one message
   Independent commands run in parallel

3. Background Long Operations
   Bash(command="python train.py", run_in_background=True)
   Continue working while command runs

4. Data Processing with jq
   Bash(command="jq '.nodes[] | select(.type==\"tool\")' data.json")
   JSON processing directly in shell

5. Git Workflows
   Bash(command="git add . && git commit -m 'message' && git push")
   Chained git operations (special safety features)

EMERGENT WORKFLOW PATTERNS
--------------------------
Pattern: Write → Bash Test → Edit Loop
  Write code → Test with Bash → Fix with Edit → Repeat
  Quality assurance through testing

Pattern: Data Pipeline Processing
  Bash with pipes: command1 | command2 | command3
  Stream processing for efficient data transformation

Pattern: Validation Bash
  After Write/Edit → Bash to test → Confirm working
  Example: Bash("python -m pytest test_file.py")

Pattern: Background + Monitor + Continue
  Bash background → BashOutput to check → Continue work
  True parallelism enabling complex workflows

ANTI-PATTERNS
-------------
✗ Using Bash for file operations (use Read/Write/Edit)
✗ Using Bash echo for communication (output text directly)
✗ Interactive commands with -i flag (not supported)
✗ Forgetting quotes on paths with spaces (fails)
✗ Not using && for sequential deps (; continues on error)

CONNECTS TO
-----------
Tools: Follows Write (test code), uses BashOutput (monitor)
Capabilities: Executes all agent patterns, runs eval suites
Techniques: Implements Batch Processing, SQL Queries
Workflows: Testing, validation, data processing hub

REAL-WORLD USAGE (FROM KGF PROJECT)
-----------------------------------
- Combined JSON files with jq (data merging)
- Created SQLite database with migration script
- Ran migration script: python3 migrate_claude_api_kg.py
- Tested backend API with curl commands
- Started/stopped backend server processes
- Validated database with sqlite3 queries
Total: ~15 Bash operations for data processing and testing

2.2 TASK TOOL (AGENT LAUNCHER)
-----------------------------------------------------------------------------

OVERVIEW
--------
The Task tool launches specialized sub-agents for complex, multi-step work.
It's the implementation of the Orchestrator-Workers agent pattern.

OFFICIAL CAPABILITIES
---------------------
- Launch general-purpose or specialized agents
- Stateless (each invocation independent)
- Returns single final message (no back-and-forth)
- Can run multiple agents in parallel
- Agents have access to all tools
- Requires detailed autonomous instructions

DISCOVERED PROPERTIES
---------------------
✓ Each agent invocation is completely stateless
✓ Must provide comprehensive instructions (no clarification possible)
✓ Can launch multiple agents in one message (parallel work)
✓ Agent types: general-purpose, statusline-setup, output-style-setup
✓ Returns when agent completes (no streaming)
✓ Higher latency due to agent initialization

PERFORMANCE CHARACTERISTICS
---------------------------
Speed: Slower (agent startup overhead)
Scale: Best for complex multi-step tasks
Optimal: Autonomous work requiring multiple tools
Latency: Higher but enables parallel work

ENABLES CLAUDE API CAPABILITIES
-------------------------------
✓ Orchestrator-Workers - Direct pattern implementation
✓ Parallelization - Multiple agents at once
✓ Agent-based Workflows - Complex autonomous tasks
✓ Routing - Specialized agents for different domains

TYPICAL USAGE PATTERNS
----------------------
1. Complex Research Task
   Task(subagent_type="general-purpose",
        prompt="Research and analyze all files about X, create summary")
   Autonomous multi-step work

2. Parallel Research Agents
   [Task for topic A, Task for topic B, Task for topic C]
   Parallel independent research

3. Background Analysis
   Task in background → Continue working → Retrieve results later
   Asynchronous complex work

4. Specialized Task Delegation
   Task(subagent_type="specialized-agent",
        prompt="Configure specific subsystem")
   Domain-specific work

EMERGENT WORKFLOW PATTERNS
--------------------------
Pattern: Orchestrator Delegates to Workers
  Analyze task → Break into subtasks → Launch Task agents → Synthesize
  Direct implementation of orchestrator-workers pattern

Pattern: Parallel Independent Research
  Multiple Task agents researching different areas in parallel
  Speeds up multi-faceted research

Pattern: Continue While Agent Works
  Launch Task → Continue with other work → Retrieve results when done
  True parallelism for productivity

Pattern: Agent for Complex File Operations
  Task agent handles complex multi-file analysis
  Offload heavy lifting to specialized agent

ANTI-PATTERNS
-------------
✗ Using for simple file reads (overkill)
✗ Using when you need back-and-forth (stateless limitation)
✗ Not providing comprehensive instructions (agent can't ask)
✗ Using for trivial tasks (overhead not justified)
✗ Forgetting agents are stateless (can't maintain conversation)

CONNECTS TO
-----------
Tools: Agents use all tools (Read, Write, Bash, etc.)
Capabilities: Direct implementation of agent patterns
Techniques: Enables complex workflows and parallelization
Workflows: Foundation for orchestrator-based approaches

REAL-WORLD USAGE (FROM KGF PROJECT)
-----------------------------------
- Not used in data extraction project (direct approach faster)
- Would use for complex analysis or parallel research
- Ideal for: Multi-domain research, parallel extraction, autonomous analysis
Total: 0 usage (project didn't require agent-level complexity)

--------

OFFICIAL CAPABILITIES

- Retrieve output from running/completed shells

- Returns stdout and stderr with shell status
- Supports optional regex filtering
- Shell IDs from Bash tool with run_in_background

DISCOVERED PROPERTIES
---------------------
✓ Only new output returned (streaming-style)
✓ Can monitor multiple shells independently
✓ Filter parameter for targeted monitoring
✓ Returns status: running, killed, completed
✓ Use with background Bash for true parallelism

PERFORMANCE CHARACTERISTICS
---------------------------
Speed: Fast (just retrieves buffered output)
Scale: Handles large output streams
Optimal: Monitoring long-running commands
Latency: Minimal for output retrieval

ENABLES CLAUDE API CAPABILITIES
-------------------------------
✓ Batch Processing - Monitor batch job progress
✓ Agent Patterns - Monitor worker task execution
✓ Parallel Workflows - Check multiple background tasks

TYPICAL USAGE PATTERNS
----------------------
1. Monitor Background Process
   Bash(cmd, run_in_background=True) → get shell_id
   BashOutput(bash_id=shell_id) → check progress

2. Filter Specific Output
   BashOutput(bash_id=shell_id, filter="ERROR|WARNING")
   Only see error/warning lines

3. Polling Loop Pattern
   Check BashOutput periodically while doing other work
   True asynchronous monitoring

EMERGENT WORKFLOW PATTERNS
--------------------------
Pattern: Background + Monitor + Continue
  Start background Bash → Monitor with BashOutput → Continue work
  Enables true parallelism

Pattern: Multi-Task Monitoring
  Multiple background Bash → Check each with BashOutput
  Coordinate multiple parallel operations

ANTI-PATTERNS
-------------
✗ Monitoring short commands (use synchronous Bash)
✗ Not checking output until completion (loses monitoring benefit)

CONNECTS TO
-----------
Tools: Always used with Bash (run_in_background mode)
Capabilities: Enables parallel agent pattern execution
Workflows: Foundation for asynchronous operations

REAL-WORLD USAGE (FROM KGF PROJECT)
-----------------------------------
- Monitored backend server startup
- Checked running processes
- Would use more for long data processing
Total: Minimal use (most operations were fast enough for sync)

3.1 WEBFETCH TOOL
-----------------------------------------------------------------------------

OVERVIEW
--------
The WebFetch tool fetches web content and processes it with AI. It converts
HTML to markdown and extracts information based on your prompt.

OFFICIAL CAPABILITIES
---------------------
- Fetch content from URLs
- Convert HTML to markdown
- Process with AI model based on prompt
- 15-minute cache for repeated access
- Handles redirects (returns redirect info)

DISCOVERED PROPERTIES
---------------------
✓ Requires prompt describing what to extract
✓ Cache speeds up repeated access (15 min TTL)
✓ Redirect detection (tells you when redirected)
